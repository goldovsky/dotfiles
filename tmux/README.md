# tmux

Config entry point is `.tmux.conf`, which sources everything under
`.config/tmux/`:

| File | Role |
|---|---|
| `keybindings.tmux` | prefix, splits, docker-mode, sync-panes |
| `settings.tmux` | mouse, vi mode, clipboard, `display-time`… |
| `icons.tmux` | nerd font glyphs, consumed by `stylings.tmux` as `${ic_*}` |
| `stylings.tmux` | status bar, window list, colours |
| `plugins.tmux` | TPM plugin list |
| `local.tmux` | **not versioned**, machine-specific values (see below) |
| `scripts/` | helpers called by the bindings and the status bar |

Colours come from `shell/common/themes/outputs/tmux-colors.tmux`, generated by
`shell/common/themes/generate-colors.sh`.

Plugin manager is TPM, installed by hand:

```bash
git clone https://github.com/tmux-plugins/tpm ~/.tmux/plugins/tpm
# then prefix + I inside tmux
```

## Docker dev mode

Working on a project that lives inside a Docker container normally means typing
`cbdev` in every new pane, then exiting twice to close it (once for the
container shell, once for the pane). Docker-mode removes both steps: panes open
straight inside the container, and a single `Ctrl-D` closes them.

### Shortcuts

Prefix is `Ctrl+Space` (secondary prefix: `` ` ``).

| Keys | Action |
|---|---|
| `prefix` + `C-u` | Start the dev stack in a popup, **without** entering the container |
| `prefix` + `C-d` | Toggle docker-mode **for the current window** |
| `prefix` + `\|` | Vertical split — inside the container if docker-mode is on |
| `prefix` + `-` | Horizontal split — same rule |
| `prefix` + `S` | Toggle `synchronize-panes` (type once, send to every pane) |
| `Ctrl-D` | Close the container shell **and** the pane, in one keystroke |

### Visual feedback

- **Status bar, right**: Docker icon plus a dot, green when the container is up,
  red when it is down or missing.
- **Status bar, left**: the session badge turns amber with a Docker icon when
  the current window is in docker-mode (green otherwise).
- **Window list**: a Docker icon marks each window currently in docker-mode.

### How it works

`@docker_mode` is a **window** option, set with `setw`. Two things read it:

1. the split bindings, which choose between a normal split and one running
   `scripts/dev-shell.sh`;
2. the status bar formats, for the badge and the window markers.

Because it is per window, opening a brand new window (`prefix` + `c`) still
gives a plain host shell — the usual "I just need a quick shell" case.

> **Why not `default-command`?** That option would make tmux open every new pane
> in the container automatically, which is tempting. But it only exists at
> *session* level, so new windows would inherit it too. Hence the decision is
> made in the split bindings instead.

> **Why not prefix every typed command with `docker exec`?** Because each
> `docker exec` is a brand new process: `cd` would not persist, nor would
> exported variables, activated virtualenvs or background jobs. Every command
> would restart from the container root. A persistent shell per pane is the only
> workable model.

Toggling also converts the panes that are **already open**, via
`scripts/dev-mode-apply.sh`, with one firm rule: **only idle panes are
switched**. A pane running a server, a build or an editor is left alone and
reported in the status message, because switching it means respawning it, which
would kill the process.

Going back to the host does **not** kill the pane either: `Ctrl-D` is sent to
the container shell. If it is idle it exits cleanly, leaving no orphan behind;
if it is busy the running command swallows the keystroke and the pane is left
untouched.

### Scripts

| Script | Role |
|---|---|
| `dev-shell.sh` | Opens the container shell. Translates the host cwd to its container counterpart, and falls back to a host shell (with a warning) if the container is down. |
| `dev-mode-apply.sh` | Converts already-open panes, in both directions, skipping busy ones. |
| `dev-up.sh` | Reads `@dev_up_command` and runs it. Needed because `display-popup` does not expand `#{...}` formats. |
| `docker-status.sh` | Prints the coloured dot for the status bar. |

## `local.tmux`

Machine-specific values live in `~/.config/tmux/local.tmux`, which is **not
versioned** and sourced by `.tmux.conf` only if it exists. Without it the config
works fine, docker-mode simply has nothing to target.

```tmux
# Container targeted by docker-mode and by the status bar dot.
set -g @dev_container "callbot_dev"

# User to open the shell as (see the dev service in docker-compose.yml).
set -g @dev_user "developer"

# Mounted volume mapping: <host path> -> <container path>.
# Lets a split opened in docker-mode land in the matching directory.
set -g @dev_host_root      "/home/fvlb5625/git/callbot/src"
set -g @dev_container_root "/home/developer/src"

# Stack startup command (prefix + C-u), run inside a popup.
set -g @dev_up_command "/home/fvlb5625/git/callbot/src/cb-docker/bin/local/runDevContainer.sh --no-shell"

# Which already-open panes the docker-mode toggle (prefix + C-d) converts:
#   window (default) — every pane of the current window
#   pane             — the current pane only
set -g @docker_mode_scope "window"
```

### Companion change outside this repo

`prefix` + `C-u` relies on a `--no-shell` flag added to the project's own
`runDevContainer.sh`. The script already started the stack detached
(`docker compose up -d`); the flag just stops it before the final
`docker compose exec`, so it can be called from tmux without landing in the
container. That also matters for non-interactive callers: without a TTY, the
`docker compose exec` fails and `set -e` aborts the script.

Any script that starts the stack and exits works here — adapt
`@dev_up_command` to your own project.

## Gotchas

- **`prefix` + `x` on a container pane leaves an orphan.** It kills the
  host-side `docker exec` client without telling the container shell, so
  whatever ran inside keeps running, invisible from tmux. Use `Ctrl-D`, or the
  docker-mode toggle, which both exit cleanly. To inspect leftovers:
  `docker exec <container> ps -eo pid,args`.
- **Going back to the host returns to the original host directory**, not to the
  container directory you had `cd`'d into. The reverse translation is
  impossible: the `cd` happens inside the container while the host-side client
  keeps its starting directory.
- **`display-time` is set explicitly** in `settings.tmux` because
  `tmux-sensible` raises it to 4000 ms whenever it still holds tmux's 750 ms
  default. Any other value is left alone.
- **`#{?cond,a,b}` splits on commas**, and `#[fg=...,bg=...]` contains some.
  Style variants are therefore kept in separate options and referenced with
  `#{E:@name}` rather than inlined.
- **`run-shell` does not export `TMUX_PANE`** (it does expand `#{...}` formats,
  so the pane id is passed as an argument), and it runs under `/bin/sh`, so
  `$SHELL` is `/bin/sh` there — `default-shell` is read instead.
